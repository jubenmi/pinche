# 分享相册不可查看时返回主页设计

## 目标

当用户从分享链接进入相册，而该链接已经缺少访问凭证、过期或被服务端判定为不可访问时，直接进入小程序主页，不再停留在分享相册错误页，也不展示无意义的“重新加载”操作。

普通网络失败、超时或临时服务异常仍保留现有错误页和“重新加载”能力。

## 方案

在分享相册页面内集中处理不可恢复的公开分享错误：

- 分享相册路由缺少必要的会话标识或分享凭证时，直接返回主页。
- 公开分享接口返回 `403`，表示分享已过期或不可访问时，直接返回主页。
- 跳转使用 `uni.reLaunch({ url: "/pages/index/index" })`，清空失效分享页的页面栈，避免用户后退后再次落入同一错误页。
- 其他请求错误继续写入现有加载失败状态，展示“重新加载”。

该判断仅用于公开分享相册加载流程，不放入全局请求拦截器，避免影响登录鉴权、成员相册和其他业务接口的 `403` 处理。

## 页面状态与数据流

1. 分享相册页面解析路由参数。
2. 若公开分享缺少必要标识或凭证，立即重新启动到主页，不发起相册请求。
3. 若参数完整，继续请求公开分享相册。
4. 请求返回 `403` 时重新启动到主页，不提交错误展示状态。
5. 网络、超时和 `5xx` 等可恢复错误继续进入现有错误展示状态，用户可点击“重新加载”。
6. 请求成功时保持现有相册展示逻辑不变。

## 错误边界

本次不改变以下行为：

- 成员相册的 `401` / `403` 权限提示。
- 已成功加载完整公开相册后，单张聚焦媒体不可用时查看完整相册的能力。
- 相册媒体图片或视频在展示期间失效后的刷新处理。
- 全局登录失效和维护模式跳转。

## 测试

增加聚焦的源代码契约测试或页面逻辑测试，至少覆盖：

- 公开分享缺少必要参数时调用主页 `reLaunch`，且不进入错误展示状态。
- 公开分享接口返回 `403` 时调用主页 `reLaunch`，且不保留“重新加载”错误页。
- 普通网络错误或 `5xx` 不跳主页，仍标记加载失败并保留重试入口。
- 成员相册的权限错误处理不受影响。
