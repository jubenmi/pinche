# 相册标签与公开分享读取模型整体设计

日期：2026-07-26

状态：待用户书面审阅

## 1. 背景与目标

当前相册实现把多个不同概念混在一起：

- 照片标签既可能表示剧本角色，也可能携带 DM、NPC 工作人员账号的昵称或 `open_id` 回退值；
- 公开分享从持久化 `label` 推测展示文字，需要额外的隐私过滤与可信来源判断；
- 公开相册分页和媒体 URL 后台刷新都会重写相册列表、分页游标与瀑布流状态；
- 为避免并发覆盖，需要不断增加 authority、前缀重读、请求协调与卸载守卫。

这些复杂度不是产品规则本身造成的，而是领域边界不清造成的。本设计用四条不变量重新定义系统：

1. 照片标签只描述画面中的剧本角色、NPC 角色或“其他”，不描述玩家账号身份。
2. 角色表是标签名称的唯一真相来源；照片标签不保存名称副本。
3. 公开分享保存生成分享时的冻结媒体清单。
4. 分页只改变清单尾部，后台刷新只更新已有卡片状态，两者不写同一类状态。

本设计取代
`docs/superpowers/specs/2026-07-25-public-album-label-scroll-continuity-design.md`
中的补丁式公开标签投影、已加载分页前缀重读和共享请求协调方案。

## 2. 产品语义

### 2.1 标签类型

相册只允许三类标签：

| 类型 | 含义 | 名称来源 |
| --- | --- | --- |
| `role` | 剧本中的玩家角色 | 场次角色位 |
| `npc_role` | 剧本中的 NPC 角色 | 场次 NPC 角色表 |
| `other` | 风景、场景或无法归入角色的内容 | 固定文字“其他” |

DM、NPC 工作人员、组织者或其他玩家账号不是照片内容标签。工作人员扮演角色时，应标注其扮演的剧本角色或 NPC 角色。

### 2.2 名称更新

照片只保存角色引用，不保存角色名副本。角色或 NPC 角色改名后：

- 成员相册显示最新名称；
- 已生成的公开分享也显示最新名称；
- 不需要批量更新照片标签或分享快照。

### 2.3 公开分享快照

公开分享在创建时冻结有序媒体 ID 清单：

- 分享创建后新增的照片不进入旧分享；
- 已撤回、审核失效或失去公开资格的媒体必须立即不可访问；
- 角色名称不是快照字段，仍从角色表实时解析。

## 3. 数据模型

### 3.1 规范化照片标签

新建 `session_album_media_tags`：

```text
id
media_id
kind: role | npc_role | other
seat_id nullable
npc_role_id nullable
created_at
```

数据库约束：

- `kind = role` 时，只允许有效的 `seat_id`；
- `kind = npc_role` 时，只允许有效的 `npc_role_id`；
- `kind = other` 时，两个引用均为空；
- 被引用角色必须与媒体属于同一个场次；
- 同一媒体不能重复标注同一角色或重复标注“其他”；
- 表中不存在 `label`、`user_id`、昵称、`open_id` 或其他账号字段。

数据库若无法用普通外键表达“引用必须属于同场次”，写入服务必须在同一事务中锁定并验证媒体与角色归属；相应不变量由集成测试覆盖。

### 3.2 冻结分享清单

新建或规范化 `session_album_public_share_items`：

```text
share_id
ordinal
media_id
created_at
```

约束：

- `(share_id, ordinal)` 唯一；
- `(share_id, media_id)` 唯一；
- 创建分享时一次性写入完整、有序清单；
- 分享存续期间不追加新媒体。

分页游标只编码并签名 `share_id + ordinal`，不携带客户端可修改的查询状态。

## 4. 服务端职责

### 4.1 AlbumTagResolver

接口：

```text
resolveAlbumTags(sessionId, mediaIds)
  -> Map<mediaId, Array<{ kind, refId, label }>>
```

职责：

- `role` 关联场次角色位并读取最新角色名；
- `npc_role` 关联场次 NPC 角色并读取最新名称；
- `other` 返回固定文字“其他”；
- 丢弃缺失、跨场次或已失效的角色引用；
- 保持标签排序稳定。

禁止：

- 查询 `users` 表；
- 接受持久化自由文本作为角色名；
- 返回玩家 ID、昵称、头像或 `open_id`。

成员相册与公开分享必须调用同一个 resolver，不允许各自实现标签投影。

### 4.2 PublicShareManifest

职责：

- 创建冻结的有序媒体清单；
- 根据签名 ordinal cursor 分页；
- 每次读取时复核媒体仍属于清单且具有公开资格；
- 对已失效项目执行跳过并继续填充当前页；
- 使用 `AlbumTagResolver` 补充当前角色标签。

输出只包含公开展示所需字段，不包含上传者身份、原始标签对象、对象 Key、ETag 或作者私有字段。

### 4.3 PublicMediaState

接口：

```text
refreshPublicMediaState(shareToken, mediaIds)
  -> {
       patches: Array<{
         mediaId,
         mediaUrls,
         expiresAt,
         tags
       }>,
       unavailableIds: mediaId[]
     }
```

职责：

- 只接受有数量上限的媒体 ID；
- 验证每个 ID 属于该分享的冻结清单；
- 重新复核公开资格；
- 为仍可见媒体签发新的访问凭证；
- 使用 `AlbumTagResolver` 返回最新角色标签；
- 对撤回或失效媒体返回 `unavailableIds`。

禁止：

- 返回新的媒体；
- 改变媒体顺序；
- 返回或修改分页游标；
- 返回完整相册列表。

## 5. 客户端读取模型

公开相册页面只保存：

```text
cards
nextCursor
pageLoading
pageError
pageGeneration
```

只允许四种状态事件：

### 5.1 INITIAL_PAGE

- 建立页面卡片和首个 cursor；
- 这是唯一允许整体建立瀑布流的事件。

### 5.2 NEXT_PAGE

- 使用当前 `nextCursor` 请求下一页；
- 按媒体 ID 去重；
- 只把新增卡片追加到现有瀑布流尾部；
- 成功后提交新 cursor；
- 不清空、不重建、不重新挂载已有卡片。

### 5.3 MEDIA_PATCH

- 将当前已显示的媒体 ID 批量发送给 `PublicMediaState`；
- 按 ID 更新 URL、到期时间和标签；
- 对 `unavailableIds` 只移除对应卡片；
- 不增加卡片，不改变剩余顺序，不修改 cursor；
- 不调用瀑布流全量 `clear` 或 refresh。

### 5.4 UNLOAD

- `pageGeneration` 加一；
- 取消可取消的请求；
- 所有响应提交前必须验证捕获的 generation；
- 晚到响应不得写入卡片、cursor、loading、error 或 timer。

## 6. 并发不变量

`NEXT_PAGE` 与 `MEDIA_PATCH` 可以并发，因为它们拥有不同状态：

| 操作 | 可写状态 | 禁止写入 |
| --- | --- | --- |
| `NEXT_PAGE` | 新卡片、`nextCursor`、分页 loading/error | 已有卡片字段、媒体刷新 timer |
| `MEDIA_PATCH` | 已有卡片字段、失效卡片、媒体刷新 timer | 新卡片、`nextCursor`、分页 loading/error |

如果后台刷新先返回，它更新已有卡片；下一页随后追加新卡片。

如果下一页先返回，它追加新卡片；本轮后台刷新不包含这些新 ID，新卡片使用分页响应中自带的最新凭证，下一轮刷新再覆盖。

因此不需要：

- 已加载分页前缀重读；
- 分页与媒体刷新共享 request authority；
- 分页/刷新协调器；
- 通过 `pageScrollTo` 补偿滚动位置。

## 7. 错误处理

- 首屏失败：显示整页重试，不建立空瀑布流后再重建。
- 下一页失败：保留已有卡片和 cursor，显示底部重试。
- 媒体状态刷新失败：不改变卡片集合，使用有最小值和最大值的延迟重试。
- 分享 token 失效：立即清空媒体访问凭证并进入分享失效状态。
- 单张媒体失效：只移除该卡片，不触发全量刷新。
- 页面卸载：取消 timer 并使 generation 失效。

## 8. 迁移策略

### 8.1 标签迁移

从旧标签表迁移：

- `seat` -> `role`；
- `session_npc_role` -> `npc_role`；
- `other` -> `other`；
- `dm`、`npc`、`organizer` 等账号身份标签不迁移。

只有能验证媒体、角色引用属于同一场次的行才迁移。无法确定的关系不得通过昵称或账号信息推断。

### 8.2 分享清单迁移

- 将现有分享中的媒体 ID 快照按原顺序展开为 share item 行；
- 保持原 token 和分享有效期；
- 重复或无效 ID 在迁移时记录审计并丢弃；
- 新旧分页接口在切换前用同一快照做结果对比。

### 8.3 发布顺序

1. 创建新表并执行可重复的回填。
2. 部署新 resolver、清单分页和媒体状态接口。
3. 部署使用四事件状态模型的客户端。
4. 观察错误率、分页重复率、媒体状态刷新失败率。
5. 确认稳定后删除旧表读取、历史标签文字投影、分页前缀重读和请求协调器。

## 9. 验证策略

### 9.1 数据库与迁移

- 三种合法标签状态可写入，其他组合被拒绝；
- 跨场次角色引用被拒绝；
- 旧账号身份标签不会迁移；
- 回填可重复执行且结果不变；
- 分享媒体顺序与迁移前快照一致。

### 9.2 服务端

- 角色改名后，成员相册和公开分享同时显示新名称；
- resolver 的查询和 DTO 不包含玩家账号字段；
- 任意持久化自由文本都不能成为公开标签；
- cursor 被篡改或绑定到其他分享时失败；
- media-state 不能查询分享清单外的媒体；
- 撤回媒体不再获得访问凭证。

### 9.3 客户端纯状态测试

- `INITIAL_PAGE` 只建立一次列表；
- `NEXT_PAGE` 只追加且按 ID 去重；
- `MEDIA_PATCH` 只更新或移除指定 ID；
- `NEXT_PAGE` 与 `MEDIA_PATCH` 以两种完成顺序执行，最终结果一致；
- 分页失败保留 cursor 和卡片；
- generation 失效后，所有晚到结果均为无操作。

### 9.4 渲染与真机验收

- 下一页加载只新增卡片 DOM，不销毁首屏卡片；
- 媒体状态刷新只更新目标卡片；
- 撤回单张媒体不触发瀑布流全量重建；
- 真机拖到底加载时，滚动位置连续且不返回顶部；
- 在分页请求期间触发 `onShow` 或 URL 刷新，下一页仍正常追加。

## 10. 明确不做

- 不保留 DM/NPC 工作人员账号标签兼容展示；
- 不在分享清单中保存角色名快照；
- 不让客户端从旧 `tag_type`、昵称或 `public_category` 推断标签；
- 不建立通用任务调度器；
- 不通过保存和恢复 scrollTop 掩盖列表重建；
- 不在本次范围内重构成员相册无关功能。

## 11. 完成标准

以下条件全部满足才算完成：

1. 成员相册和公开分享只显示最新剧本角色名、NPC 角色名或“其他”。
2. 公开标签读取链路不依赖玩家表或持久化自由文本。
3. 旧分享仍能按原媒体顺序访问。
4. 分页只追加，媒体刷新只打补丁，代码中不存在分页前缀重读与共享协调器。
5. 自动化测试覆盖数据约束、迁移、接口安全、并发顺序与卸载。
6. 微信真机确认加载更多不跳回顶部。
