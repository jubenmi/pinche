# 小程序审核首页白屏修复设计

## 背景与结论

微信审核在 `0.20260725.1623` 上看到只有原生导航栏、业务区域全白的首页。2026-07-21
的同类修复已随 `0.20260721.1758` 成为线上版本，但对比两个版本后确认：

- 首页源码、`app.js`、`app.json`、`common/vendor.js` 和首页构建产物哈希一致；
- 本次上传包大小与干净 production 构建一致，并非误传缺少启动占位的旧 dev 产物；
- 旧测试只验证 Vue 源码节点顺序，没有执行页面注册前的公共运行包。

因此不是修复代码被回退，而是旧修复只覆盖“页面已经注册、业务组件尚未就绪”的正常
路径，没有覆盖审核设备运行环境差异，也在首批数据完成前过早隐藏了启动态。

## 可复现边界

`packages/shared/src/beijingTime.js` 在模块顶层无保护构造 `Intl.DateTimeFormat`，并依赖
`formatToParts`。该模块位于首页 `common/vendor.js` 的同步启动链路中。模拟缺少完整
`Intl` 的运行环境时会在 `wx.createPage` 之前稳定抛错，此时首页 WXML 占位也不会出现。

首页健康检查成功后立即隐藏启动态，但业务组件和首批公开车局请求还没有完成，存在
启动态与业务首屏之间的第二个空窗。

## 方案

采用分层加固：

1. 业务北京时间固定为 UTC+8，使用“时间戳加八小时后读取 UTC 字段”的纯算术实现，
   移除公共 vendor 对 `Intl` 的依赖。
2. 首页配置微信 `initialRenderingCache: "static"`，让纯原生启动态先于逻辑层执行显示。
3. 把“健康检查已有结果”和“首批首页数据已结束”拆成两个状态。健康检查后先挂载业务
   组件，但启动态继续覆盖，直到首批请求成功或明确失败。
4. 自动测试直接检查 `dist/build/mp-weixin`，验证静态初始渲染、原生启动态顺序和
   vendor 中不存在 `Intl.DateTimeFormat`。

本次不捆绑 COS、TDesign 和页面分包重构；这些属于更大的包体优化，不是审核修复的
必要条件。

## 验收

- 无 `Intl`、缺少 `formatToParts`、不同时区输入下的北京时间测试通过。
- 首页源码和 production 构建启动契约通过。
- 清除微信开发者工具全部缓存后，首页先显示启动态，再进入游客首页或明确错误态。
- 严格合法域名检查下控制台 0 error。
- 只上传本次提交干净生成的 `dist/build/mp-weixin`。
