# 相册加载状态热修设计

## 目标

修复登录成员相册在照片数据已返回后仍永久显示“正在加载相册”的回归，同时恢复请求失败时的错误页与“重新加载”入口。完成后在微信开发者工具中展示修复后的本地构建。

## 范围

- 修复成员相册 `loadingAlbum` 的当前请求清理逻辑。
- 在成员相册请求开始时清除旧错误态，在当前请求失败时设置 `albumLoadFailed`。
- 增加经过 Vue 3 `reactive()` 的运行时回归测试，覆盖成功和失败两条路径。
- 扫描同类响应式对象身份比较；本次仅修改相册问题。
- 不修改公开分享相册、分享页、管理资料页或后端接口。

## 方案比较

1. **使用现有 request authority 判断当前请求（采用）**
   - `finally` 通过 `isCurrentRequest()` 判断是否清除 loading，不再把普通 owner 对象存入响应式 `data()`。
   - 优点：复用已有并发控制，避免 Vue Proxy 身份陷阱，改动最小。

2. **使用 Vue `markRaw()` 保留对象身份**
   - 能修复严格比较，但把框架响应式细节引入请求生命周期，后续仍容易误用。

3. **增加独立数字 request generation**
   - 标量比较安全，但与现有 `albumListRequestAuthority` 重复，扩大状态面。

## 状态规则

- 当前请求成功或失败：必须结束 `loadingAlbum`。
- 已过期请求完成：不得清除更新请求的 loading。
- 开始重试：清除旧的 `albumLoadFailed`。
- 当前请求失败：清空成员相册投影，设置 `albumLoadFailed=true`，展示错误页和重试按钮。
- 当前请求成功：设置 `albumLoadFailed=false`，展示照片瀑布流。

## 验证

- 用真实 Vue 3 `reactive()` 包装组件测试上下文，证明旧代码在成功后仍为 loading，修复后结束 loading。
- 模拟主相册请求失败，验证错误态为 true 且 loading 结束。
- 运行相册相关测试、历史车局检查和小程序生产构建。
- 刷新微信开发者工具，确认相册页不再被 loading 卡片遮挡，控制台无新增错误。
