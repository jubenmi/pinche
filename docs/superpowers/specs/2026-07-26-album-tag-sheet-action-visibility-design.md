# 相册标注弹层操作按钮可见性修复设计

## 目标

确保单张标注和批量标注弹层中的“取消”“保存标注”始终位于可视区域内；角色数量较多时只滚动角色内容，不让关键操作随内容移出屏幕。

## 根因

当前标注弹层把标题、已选标签、角色列表、隐私提示和操作按钮全部放在同一个普通 `view` 中，并依赖 `overflow-y: auto` 滚动。TDesign `t-popup` 默认会阻止内容层的普通触摸滚动，以避免背景页面穿透，因此角色列表变长后，末尾按钮会被推到弹层可视区外且难以到达。

## 方案

采用项目中“车内聊天”弹层已经验证的结构：

1. 标注弹层使用纵向 Flex 布局并限制在视口高度内。
2. 标题与说明保留在固定头部。
3. 已选标签、角色列表和隐私提示放入小程序原生纵向 `scroll-view`。
4. “取消”“保存标注”放在滚动区之外的固定底部操作区，并保留现有按钮状态和事件。
5. 继续由 `t-popup` 处理底部安全区，不关闭背景滚动拦截。

不改变角色选择、标签替换、保存请求、关闭行为、文案、颜色或业务权限。

## 同类检查范围

检查小程序源码中的全部 `t-popup`：

- 车内聊天：中部已使用原生 `scroll-view`，关闭和发送操作位于滚动区外，无同类问题。
- 体验记录相册选图：图片网格已使用原生 `scroll-view`，“完成”位于固定头部，无同类问题。
- 相册标注：本次修复目标，也是当前唯一依赖普通 `view` 滚动并把关键操作放在内容末尾的弹层。

## 错误处理与状态

保存期间继续禁用两个按钮并显示“保存中...”；保存失败时沿用现有反馈并保持弹层可操作。关闭弹层、点击遮罩和选中角色的行为保持不变。

## 测试与验收

1. 先添加源码结构回归测试，证明当前标注弹层未使用原生滚动区且操作区位于滚动内容末尾。
2. 修复后测试确认：原生滚动区存在，操作区位于滚动区之外，弹层容器不会整体滚动。
3. 运行相册相关单元检查、小程序构建和静态检查。
4. 在长角色列表下验证：打开弹层后两个按钮立即可见；滚动角色列表时按钮不移动；底部安全区不遮挡按钮。
5. 在短角色列表、单张标注、批量标注和保存中状态下复核布局与行为。

## 非目标

- 不重做角色卡片视觉。
- 不调整弹层高度、业务文案或标签数据结构。
- 不修改非弹层页面的底部操作栏。
