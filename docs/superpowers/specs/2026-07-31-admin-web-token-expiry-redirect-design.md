# Admin Web Token 过期自动返回登录页设计

## 背景

管理后台会把 token、用户资料和角色缓存到浏览器本地存储。当前受保护接口返回 HTTP 401 时，请求层只抛出后端错误消息；各业务工作区随后把 `Token expired` 渲染为页面错误，但根组件仍保留旧 token，因此页面不会回到登录界面。

本次变更只修复管理后台的登录过期处理，不调整 token 有效期、登录协议、角色权限或后端鉴权规则。

## 目标

- 已携带管理后台 token 的请求收到 HTTP 401 后，立即清除本地登录态并显示登录页。
- HTTP 403 继续作为权限不足错误交给当前页面处理，不触发退出。
- 未携带 token 的请求收到 HTTP 401 时不触发全局退出，避免干扰登录流程和匿名请求。
- 多个并发请求同时返回 401 时，退出处理保持幂等。
- 业务页面不再停留并展示 `Token expired`。

## 非目标

- 不实现 refresh token 或静默续期。
- 不更改后端返回格式或 JWT 过期时间。
- 不引入新的全局状态管理库或路由框架。
- 不把 403、媒体 URL 过期或普通网络错误视为登录过期。

## 方案比较

### 方案 A：请求层统一发布登录过期事件（采用）

公共请求层在请求开始时记录是否携带 token。响应解析发现 HTTP 401 且该请求携带 token 时，清除本地登录态并发布一个浏览器内的登录过期事件。根组件订阅事件并刷新自身鉴权状态，Vue 随即卸载业务工作区并渲染登录组件。

优点是鉴权判定集中、所有普通 JSON 和表单请求自动覆盖，同时根组件仍是界面状态的唯一拥有者。事件和清理操作天然可以重复执行，适合多个并发请求同时失败的情况。

### 方案 B：各业务组件分别捕获 401

每个工作区在 `catch` 中判断 401 并调用退出逻辑。改动分散，后续新增接口容易遗漏，也会把全局鉴权行为复制到多个业务组件，因此不采用。

### 方案 C：引入集中式状态管理与路由守卫

使用新的状态管理和路由体系管理登录生命周期。长期扩展性更强，但会扩大本次修复范围并增加回归风险，因此不采用。

## 组件与职责

### `apps/admin-web/src/api.js`

- 保持本地鉴权数据的读写与清理职责。
- 公共响应处理函数接收“请求发出时是否携带 token”的上下文。
- 仅当响应状态为 401 且请求确实携带 token 时：
  1. 调用现有 `clearStoredAuth()`；
  2. 发布一次语义明确的登录过期事件；
  3. 继续抛出原始 API 错误，让调用方 Promise 正常结束。
- `apiRequest` 和 `apiFormDataRequest` 都传递相同上下文，避免上传/表单请求成为例外。
- 403、匿名 401 和其他错误只抛错，不修改登录态。

### `apps/admin-web/src/App.vue`

- 根组件在挂载时订阅登录过期事件，在卸载时移除监听器。
- 收到事件后，通过现有鉴权读取逻辑把响应式 `auth` 更新为空登录态，同时关闭资料弹层和重置头像加载状态。
- 手动退出继续复用同一套本地清理和界面重置行为。
- 当 `auth.token` 为空时，现有模板条件自动切换到 `LoginPanel`，无需新增路由或强制刷新页面。

## 数据流

1. 用户已登录，业务组件发起带 Bearer token 的请求。
2. 后端检测到 token 过期并返回 HTTP 401 JSON。
3. 请求层解析响应，确认请求发出时携带 token。
4. 请求层清除 token、用户和角色缓存，并发布登录过期事件。
5. 根组件收到事件，将响应式鉴权状态更新为空。
6. Vue 卸载当前业务工作区并显示登录页。
7. 原请求仍以原始错误结束；由于业务工作区已卸载，页面不会继续保留 `Token expired` 错误条。

## 并发与边界处理

- 多个请求同时返回 401 时，重复移除相同本地存储键是安全的；根组件重复写入空鉴权状态也不会改变最终结果。
- 以“请求开始时是否存在 token”为判断依据，避免第一个 401 清理 token 后，后续同批响应因读取到空 token 而漏掉一致处理。
- HTTP 403 不清理登录态，以保留角色不足、资源不可访问等业务语义。
- 媒体请求现有的 `MEDIA_URL_EXPIRED` 重试逻辑不纳入本次全局退出，避免临时媒体授权失效导致整个后台退出。
- 登录票据轮询和其他匿名请求即使返回 401，也不会触发全局退出。

## 测试设计

新增管理后台鉴权响应单元测试，使用可控的本地存储、事件目标和响应对象验证：

1. 带 token 的请求收到 401：清除 token、用户和角色，并发布登录过期事件。
2. 带 token 的请求收到 403：保留登录态，不发布事件，仍抛出权限错误。
3. 未带 token 的请求收到 401：不发布事件，不执行全局退出。
4. 两个带 token 的 401 连续处理：最终状态为空且不会产生异常。
5. 现有 API 错误字段（状态码、错误码、详情）仍保持原有形状。

同时运行管理后台单元测试、`d12` 管理后台契约检查和生产构建，确认没有破坏现有页面、上传流程与构建配置。

## 验收标准

- 复现截图场景时，接口 401 后不再停留在管理界面展示 `Token expired`。
- 页面自动显示现有登录面板，本地 token、用户和角色缓存均已清空。
- 403 响应仍在当前页面显示权限类错误且用户保持登录。
- 自动化回归测试、管理后台检查和生产构建全部通过。
