# 车局统一分享页设计

## 目标

把“邀请上车”和“认领相册”收敛为同一个分享功能、同一个页面和同一套席位组件。

- 发车前是拼车模式：邀请玩家上车并认领空位。
- 发车后是认领模式：邀请本局玩家认领自己玩过的角色与照片。

分享入口、页面路由、车局数据加载、邀请 token 和接收方落地链路全部复用。页面根据服务器返回的车局生命周期自动切换模式，避免旧分享链接进入错误页面。

## 关键约束

- 整个小程序只使用 WebView，不引入 Skyline。
- 复用现有 `/pages/session/share`，不新增第二个分享页。
- 生产实现直接复用现有 `RoleSeatBoard`。
- 微信分享使用随模式选择的固定图片。
- 不使用页面截图、Skyline `snapshot`、Canvas 或动态海报。
- 相册入口只负责打开统一分享页，不直接触发微信分享。

## 页面模式

| 车局状态 | 页面模式 | 目的 | 主文案 | 分享按钮 |
| --- | --- | --- | --- | --- |
| 未发车 | `join` | 邀请玩家加入车局并认领空位 | `邀请玩家上车` | `分享拼车邀请` |
| 已发车 | `claim` | 邀请同局玩家认领角色和照片 | `邀请本局玩家认领照片` | `分享给玩家认领` |

“已发车”由服务端车局生命周期字段判断；如果暂时没有明确状态字段，则使用服务端时间与 `startAt` 判断。`entry`、`source` 等 URL 参数只记录入口来源，不能决定业务模式。

已发车但照片尚未上传时，玩家仍可先认领角色。认领完成后显示：

```text
角色已认领，照片上传后即可查看
```

## 产品语言

### 拼车模式

- 页面标题：`邀请上车`
- 主说明：`邀请玩家加入本局`
- 辅助说明：`选择一个空位，和大家一起开局。`
- 分享按钮：`分享拼车邀请`
- 席位状态：沿用现有上车状态文案

### 认领模式

- 页面标题：`邀请认领`
- 主说明：`邀请本局玩家认领照片`
- 辅助说明：`选择自己玩过的角色，认领对应照片。`
- 分享按钮：`分享给玩家认领`
- 席位状态：`待认领`、`已认领`、`我认领`

认领模式禁止出现：

- `上车`
- `发车`
- `还差几位`
- `招募玩家`
- 任何暗示玩家尚未参加游戏的说明

## 页面结构

统一分享页按顺序显示：

1. 登录身份提示。
2. 紧凑场次摘要：剧本、店家、时间和备注。
3. 现有 `RoleSeatBoard`。
4. 当前模式的辅助说明。
5. 原生微信分享按钮。

页面沿用现有宣纸白、墨绿、细边框和票券语言。六角色场次需要在常见手机首屏内看到主要席位和分享按钮，便于页面验收和人工截图；但微信分享卡片不使用页面截图。

### 角色席位

生产代码直接复用现有 `RoleSeatBoard` 和真实车局数据。

- 不把设计稿或页面截图作为席位图片。
- 不复制一份专用于认领模式的席位组件。
- 拼车模式显示空位选择和已有成员。
- 认领模式显示角色认领状态。
- 模式差异通过明确的 props 或页面数据传给组件，不在组件内部猜测 URL 来源。

### 分享按钮

统一分享页使用原生 `<button open-type="share">`，避免自定义组件边界丢失 dataset 或分享意图。

`onShareAppMessage` 不依赖按钮 dataset。它根据已经加载的车局状态生成当前模式的标题、固定图片和落地路径。

## 入口与路由

所有入口打开同一个页面：

```text
/pages/session/share?id=<sessionId>&entry=<entry>
```

入口示例：

- 车局详情的分享入口：`entry=session`
- 相册的“邀请认领”入口：`entry=album`
- 微信分享落地：`entry=wechat_share`

相册工具入口的文案从 `招募` 改为 `邀请认领`。它只执行 `navigateTo`，不直接使用 `open-type="share"`，从而不再依赖相册按钮的 dataset 判断分享意图。

同一个历史链接在发车前打开时显示拼车模式；发车后再次打开时显示认领模式。

## 数据流

### 发起方

1. 入口携带 `sessionId` 打开统一分享页。
2. 页面加载服务端车局快照和生命周期状态。
3. 页面据此确定 `join` 或 `claim` 模式。
4. 页面加载现有席位数据和当前玩家状态。
5. 页面准备可分享的邀请 token。
6. token 准备完成后启用原生分享按钮。
7. `onShareAppMessage` 返回当前模式的分享载荷。

分享路径：

```text
/pages/session/share
  ?id=<sessionId>
  &shareCode=<shareCode>
  &inviteToken=<inviteToken>
  &entry=wechat_share
  &source=<join|claim>
```

`source` 仅用于统计和排查。接收方仍以服务端实时车局状态决定页面模式。

### 接收方

1. 玩家从微信分享卡片进入统一分享页。
2. 页面使用 `id` 和 `inviteToken` 加载实时车局状态。
3. 未发车时，玩家选择空位并完成上车。
4. 已发车时，玩家选择自己实际玩过的角色并完成认领。
5. 认领后若照片已存在则进入相册；否则停留在成功状态，等待照片上传。

## 固定分享图片

微信卡片图片按实时模式选择，不生成动态图片：

| 模式 | 固定图片 | 卡片标题 |
| --- | --- | --- |
| `join` | 复用现有拼车固定图；实现时确认其清晰度与微信卡片比例 | `《<剧本名>》正在拼车` |
| `claim` | `/static/art/photo-claim-share.jpg` | `《<剧本名>》照片待认领` |

认领固定图为 5:4 横图，文件尺寸约 1402 × 1122，使用宣纸、水墨山景和老照片元素，文案为：

```text
本局照片待认领
邀请同局玩家认领角色与照片
```

固定图片不包含玩家头像、实时空位数、角色认领结果或二维码，避免状态过期。

## WebView 配置

整个项目维持 WebView 渲染。不得新增任何页面级或全局 Skyline 配置。

实现时需要确认：

- `pages/session/share` 使用默认 WebView，或明确配置 `renderer: "webview"`。
- 相册页和其他页面不设置 `renderer: "skyline"`。
- 开发者工具私有配置不启用 Skyline。
- 不新增 Skyline 专属组件、样式或渲染分支。

## 错误处理

- 缺少车局 ID：显示“车局信息不存在”，不展示空白页。
- 车局加载失败：保留页面骨架并提供重试。
- 邀请 token 创建失败：禁用分享按钮并允许重新准备。
- 分享前车局状态发生变化：重新获取状态并生成正确模式的载荷。
- 拼车空位已被占用：刷新席位并提示重新选择。
- 角色已被他人认领：刷新席位并提示重新选择。
- 分享载荷构造失败：留在统一分享页，不返回错误相册路径。
- 未登录接收方：完成登录后回到同一邀请路径，保留车局和 token。

## 测试策略

### 自动化测试

1. 车局分享入口和相册“邀请认领”入口都导航到 `/pages/session/share`。
2. 导航 URL 包含正确的车局 ID 和入口来源。
3. 服务端返回未发车状态时渲染 `join` 模式。
4. 服务端返回已发车状态时渲染 `claim` 模式。
5. URL 中伪造 `source` 不能覆盖服务端决定的模式。
6. 分享路径包含 `id`、`shareCode`、`inviteToken`、`entry` 和 `source`。
7. 两种模式分别返回正确标题和固定图片。
8. 缺少 token 时不可分享，并显示可见错误。
9. 模板使用原生分享按钮。
10. `RoleSeatBoard` 仍由统一分享页直接复用。
11. 配置中不存在 `renderer: "skyline"` 或其他 Skyline 启用项。
12. 实现中不存在截图、Canvas 或动态海报生成链路。

### 手工验证

1. 从未发车车局进入分享页，确认显示拼车模式。
2. 分享后，接收方可以选择空位并上车。
3. 同一车局发车后重新打开原链接，确认自动切换为认领模式。
4. 从相册点击“邀请认领”，确认进入同一个分享页。
5. 认领模式不出现“上车”“还差几位”等拼车文案。
6. 两种模式均复用现有席位视觉和交互。
7. 微信好友和群聊卡片使用对应固定图片。
8. 接收方能认领角色；照片存在时可进入相册。
9. 缺少参数或加载失败时有可见提示，不出现空白页。
10. iOS、Android 各验证一次，并确认页面均为 WebView。

## 范围边界

本次包含：

- 统一分享页双模式。
- 相册入口从直接分享改为导航。
- 车局生命周期驱动的文案和动作切换。
- 原生分享按钮、邀请 token 和正确落地路径。
- 两种模式的固定分享图片选择。
- 接收方上车或角色认领链路验证。

本次不包含：

- 引入 Skyline。
- 保存海报到相册。
- 页面截图、Canvas 或动态海报导出。
- 重做或复制 `RoleSeatBoard`。
- 新的角色或照片权限模型。
- 在认领模式公开招募未参与本局的玩家。

## 验收标准

- 全项目不引入 Skyline，相关页面继续使用 WebView。
- 发车前与发车后复用同一个分享功能和 `/pages/session/share`。
- 页面模式由服务端车局状态决定。
- 发车前可以邀请玩家上车；发车后可以邀请本局玩家认领角色与照片。
- 认领模式没有开局前招募语义。
- 生产实现直接复用现有 `RoleSeatBoard`。
- 微信卡片使用固定图片，不依赖页面截图或动态生成。
- 任何失败状态都有可见提示，不再出现“该内容暂不可分享”卡片或空白相册页。
