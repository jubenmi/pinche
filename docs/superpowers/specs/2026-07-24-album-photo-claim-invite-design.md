# 相册照片认领邀请页设计

## 目标

把相册页当前的“招募”直接分享改成两步流程：

1. 用户在车局相册点击“邀请认领”。
2. 小程序打开独立的照片认领邀请页。
3. 用户确认场次与角色认领状态后，点击“分享给玩家认领”。
4. 同局玩家从微信分享卡片进入邀请页，选择自己玩过的角色并认领对应照片。

本功能发生在游戏结束、照片已经上传之后。它不是开局前招募，也不用于邀请新人加入车局。

## 产品语言

页面与分享卡片统一使用以下语义：

- 入口：`邀请认领`
- 页面标题：`邀请认领`
- 主说明：`邀请本局玩家认领照片`
- 分享按钮：`分享给玩家认领`
- 状态：`待认领`、`已认领`、`我认领`

禁止出现：

- `上车`
- `发车`
- `还差几位`
- `招募玩家`
- 任何暗示游戏尚未开始的说明

## 渲染方案

采用页面级混合渲染：

- 现有相册页继续使用 Skyline。
- 照片认领邀请页明确使用 WebView。
- Skyline 相册通过普通 `navigateTo` 打开 WebView 邀请页。
- 从邀请页返回时回到原 Skyline 相册，不重建另一套相册页面。

原因：

- 相册的图片浏览、滚动与手势继续获得 Skyline 的渲染收益。
- 邀请页只有场次摘要、六个左右的角色席位和一个分享按钮，不需要 Skyline 的长列表或高频动画能力。
- 现有 `RoleSeatBoard` 使用 CSS Grid；Skyline 不支持 `display: grid`，切换后无法原样复用。
- 此前的错误来自 TDesign 自定义按钮未透传分享 dataset，与渲染引擎无关。

页面 renderer 必须写入受版本控制的页面配置，不能只依赖开发者工具的私有开关：

```json
{
  "path": "pages/session/album",
  "style": {
    "renderer": "skyline"
  }
},
{
  "path": "pages/session/share",
  "style": {
    "renderer": "webview"
  }
}
```

实现时保留相册已有的 Skyline 导航、滚动和 renderer 选项，仅补充或确认邀请页的 WebView 配置。

Skyline `snapshot` 或 Canvas 海报导出不在本次范围。当前目标是让 WebView 邀请页在常见手机首屏内完整呈现，方便用户直接截图分享。

## 页面与组件

### 相册入口

修改相册页的工具入口：

- 文案从 `招募` 改为 `邀请认领`。
- 入口只执行页面跳转，不直接使用 `open-type="share"`。
- 跳转目标为现有 `/pages/session/share` 页面，并携带车局 ID 与相册来源参数。
- 相册页不再依赖按钮 dataset 判断此次分享意图，也不再为该入口返回单图分享失败载荷。

建议 URL：

```text
/pages/session/share?id=<sessionId>&entry=album
```

保留 `entry=album`，避免新增一个只用于区分文案的路由参数。

### 照片认领邀请页

复用现有 `pages/session/share.vue`，不新建重复页面。

页面结构按顺序为：

1. 登录身份提示。
2. 紧凑场次摘要：剧本、店家、时间和备注。
3. 现有角色席位组件。
4. 隐私说明：`仅分享给本局玩家`。
5. 原生微信分享按钮：`分享给玩家认领`。

相册来源下的页面说明为：

```text
邀请本局玩家认领照片
把邀请发给同局玩家，选择自己玩过的角色。
```

页面继续使用现有宣纸白、墨绿、细边框和票券语言。信息压缩到常见手机首屏；六角色场次不要求滚动后才能看到分享按钮。

### 角色席位

生产代码直接复用现有 `RoleSeatBoard` 组件和真实数据。

- 不把设计稿或页面截图作为席位图片。
- 不重新设计席位卡、头像、性别颜色或选中状态。
- 不复制一份专用于邀请页的席位组件。
- 认领状态仍由现有车局席位数据计算。

设计稿中使用的席位截图只用于确认布局比例。

### 分享按钮

邀请页使用原生 `<button open-type="share">`，避免自定义组件边界再次丢失 dataset 或分享意图。

分享回调不依赖按钮 dataset。它根据当前页面已加载的车局、邀请 token 和来源生成载荷。

## 数据流

### 发起方

1. 相册页已持有 `sessionId`。
2. 在 Skyline 相册点击“邀请认领”，通过 `navigateTo` 跳转到 WebView 邀请页。
3. 邀请页加载车局快照、角色席位和当前认领状态。
4. 邀请页准备可分享的邀请 token。
5. token 准备完成后启用原生分享按钮。
6. `onShareAppMessage` 返回照片认领邀请路径。

分享路径：

```text
/pages/session/share
  ?id=<sessionId>
  &entry=album
  &shareCode=<shareCode>
  &inviteToken=<inviteToken>
  &source=wechat_share
```

### 接收方

1. 玩家从微信分享卡片进入邀请页。
2. 页面使用 `id` 和 `inviteToken` 加载可认领的角色。
3. 玩家选择自己实际玩过的角色。
4. 认领成功后进入相册或回到相册入口。
5. 相册按照已认领角色展示该玩家有权查看或管理的照片。

## 分享卡片

分享标题必须表达照片认领，不表达招募：

```text
《<剧本名>》照片待认领
```

分享卡片落地页始终是邀请页，不能回落到缺少车局参数的相册页。

如果必要参数不存在，不调用微信分享面板，并在当前页提示：

```text
认领邀请尚未准备好，请稍后重试
```

## 错误处理

- 缺少车局 ID：显示明确的“车局信息不存在”，不展示空白页。
- 车局加载失败：保留页面骨架并提供重试。
- 邀请 token 创建失败：禁用分享按钮并允许重新准备。
- 角色已经被他人认领：刷新席位状态并提示玩家重新选择。
- 分享载荷构造失败：留在邀请页，不返回单图分享失败卡片。
- 未登录接收方：完成登录后回到同一邀请路径，保留车局和 token。

## 测试策略

### 自动化测试

1. 相册“邀请认领”入口只导航，不触发直接分享。
2. 导航 URL 包含正确的车局 ID 和 `entry=album`。
3. 相册页面配置保持 `renderer=skyline`。
4. 邀请页面配置明确为 `renderer=webview`。
5. 邀请页分享路径包含 `id`、`entry`、`shareCode`、`inviteToken` 和 `source=wechat_share`。
6. 分享标题使用“照片待认领”，不包含“上车”“发车”或“招募”。
7. 缺少 token 时返回不可分享状态，而不是错误相册路径。
8. 模板使用原生分享按钮。
9. `RoleSeatBoard` 仍由邀请页直接引用，没有复制组件或截图资源。

### 手工验证

1. 确认相册实际运行在 Skyline。
2. 从已结束车局的 Skyline 相册点击“邀请认领”。
3. 确认打开的邀请页实际运行在 WebView。
4. 邀请页首屏完整显示场次、六个席位和分享按钮。
5. 截图不需要滚动拼接。
6. 微信好友和群聊分享卡片标题正确。
7. 接收方打开分享卡片后能看到同一车局和实时席位状态。
8. 接收方选择角色、认领成功并进入相册。
9. 从邀请页返回后仍回到原 Skyline 相册，筛选和滚动状态没有异常丢失。
10. iOS、Android 各验证一次。

## 范围边界

本次包含：

- 相册入口改为导航。
- 邀请页照片认领语义与单屏布局。
- 原生分享按钮与正确分享载荷。
- 接收方角色认领链路验证。

本次不包含：

- 改造或重写现有 Skyline 相册。
- 保存海报到相册。
- Canvas 或 `snapshot` 图片导出。
- 重做 `RoleSeatBoard`。
- 新的角色或照片权限模型。
- 公开招募未参与本局的玩家。

## 验收标准

- 相册点击“邀请认领”必定打开邀请页，不直接弹出微信分享。
- 相册继续使用 Skyline，邀请页明确使用 WebView。
- 页面与分享卡片没有开局前招募语义。
- 页面生产实现直接复用现有 `RoleSeatBoard`。
- 六角色场次可在常见手机首屏中完成截图。
- 分享卡片落地后可选择真实角色并完成照片认领。
- 任何失败状态都有可见提示，不再出现“该内容暂不可分享”卡片或空白相册页。
