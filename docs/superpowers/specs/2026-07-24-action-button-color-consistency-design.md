# 全项目可用按钮绿色一致性设计

日期：2026-07-24

## 1. 背景与目标

当前项目已经形成以深绿为主的品牌操作色，但按钮实现分散在小程序全局样式、页面局部样式、TDesign `t-button`、原生 `button`、共享聊天组件和后台网页样式中。部分仍可点击的文字按钮继续使用组件默认灰色、白色或中性灰底，导致它们看起来像禁用状态。相册隐私页的“保存设置”是已确认的复现入口。

本次改造的目标是：

- 所有可用的文字操作按钮都使用项目现有、协调的绿色视觉语言。
- 灰色只表达真实禁用或不可操作状态。
- 红色继续专用于删除、停止分享等危险操作。
- 在不重做页面布局的前提下，清理小程序、共享组件和后台网页中的同类遗留。
- 增加自动化约束，防止新的可用灰色按钮再次进入项目。

## 2. 已确认产品规则

### 2.1 状态与颜色

按钮颜色由交互语义决定：

| 语义 | 视觉规则 |
| --- | --- |
| 可用的主要或标准文字操作 | 使用现有品牌深绿；小程序优先复用 `#1f6f5b` 或现有 `#1a5d4d → #2b765f` 渐变，文字为白色 |
| 可用的低强调文字操作 | 仍使用绿色体系，可采用浅绿色底、绿色边框和深绿色文字；不得使用灰底、白底加灰边来表达主次 |
| 禁用或提交中不可操作 | 使用现有中性灰，取消阴影，并同时具备真实 `disabled` 属性或等价的不可交互守卫 |
| 危险操作 | 保留现有红色体系，不改成绿色 |

“绿色”指项目已有的沉稳深绿和同色系浅绿，不引入荧光绿、高饱和亮绿或新的独立品牌色。

### 2.2 纳入范围

纳入审计：

- `apps/miniprogram/src` 下业务页面和业务组件中的 `t-button`、原生 `button` 及等价文字操作控件。
- `apps/miniprogram/src/extensions/session-pseudo-chat` 中的小程序聊天扩展。
- `packages/talk/miniprogram` 中与扩展保持同步的共享聊天源文件。
- `apps/admin-web/src` 下后台页面和组件中的文字按钮。
- 全局和局部 CSS 中直接控制上述按钮背景、边框、文字色和禁用态的规则。

不纳入颜色统一：

- 纯图标按钮，例如关闭、更多、查看大图、浮动工具图标。
- 标签、徽标、状态胶囊、筛选项、分段选择器、单选/复选控件。
- 卡片本身的点击区域和列表行。
- 微信或组件平台强制呈现、业务代码无法控制外观的系统入口。
- 第三方源码目录 `wxcomponents` 和 `uni_modules`；业务侧通过参数或外层 class 控制其主题，不直接修改供应商代码。

### 2.3 主次层级

可用按钮不再依靠中性灰表示“次要”。主次层级改由以下方式表达：

- 主要操作使用深绿实底或现有深绿渐变。
- 低强调操作使用现有浅绿底配深绿文字/边框，或缩小尺寸、降低阴影。
- 危险操作保持红色，并避免与绿色主操作同等强调，除非页面确实要求用户在两者中明确选择。
- 同一操作区存在多个可用按钮时，允许颜色深浅不同，但每个按钮都必须明显属于绿色体系。

## 3. 根因与改造边界

已确认的根因不是单个页面配色错误，而是按钮主题存在多条并行路径：

1. 小程序全局 `.button` 已定义绿色，但未声明 `theme` 的 `t-button` 会使用 TDesign `.t-button--default`：其组件默认背景为 `#e7e7e7`，并覆盖业务层期望的绿色。
2. `.button.secondary` 目前使用白底和中性边框，仍可点击时容易被识别为灰色或禁用。
3. 相册隐私页“保存设置”只写了 `class="button"`，未传 TDesign `theme`/`custom-style`，因此当前实际呈现为默认灰色；同类写法存在相同风险。
4. 多个页面定义了自己的 `.mini-button`、`.action-button`、`.tool-button` 或内联 `custom-style`，其中包含灰色、白色和中性背景。
5. 后台网页同时存在原生 `button`、`.primary`、`.secondary-action`、`.action-button` 等规则，语义与颜色没有统一绑定。

本次只收敛按钮的状态与颜色契约，不重构页面结构，不替换 UI 框架，也不创建跨小程序和网页运行时共享的 Button 组件。

## 4. 样式架构

### 4.1 小程序

小程序继续以 `apps/miniprogram/src/App.vue` 为基础按钮契约：

- `.button`：可用深绿实底/渐变、白字。
- `.button.secondary`：改为绿色低强调样式，不再使用中性白灰样式。
- `.button.disabled`、原生/TDesign `disabled`：中性灰且不可交互。
- `.button.danger`：红色。

对 TDesign `t-button`：

- 业务页面优先显式使用可控的主题、class 或 `custom-style`。
- 对组件内部 CSS 变量设置现有绿色值，避免宿主 class 生效而内部按钮仍显示默认灰色。
- 只有组件优先级确实覆盖全局契约的页面才增加局部覆盖，不在每个页面复制完整色值。

对局部按钮类：

- 保留与布局相关的宽高、圆角、间距和定位。
- 删除或替换会把可用按钮变成中性灰/白的背景、边框和文字色。
- 危险、禁用和非文字按钮的局部样式保持语义化例外。

### 4.2 共享聊天组件

`apps/miniprogram/src/extensions/session-pseudo-chat` 和 `packages/talk/miniprogram` 的镜像文件必须同步修改并由现有同步/一致性检查覆盖，避免应用内版本和包源版本出现不同按钮颜色。

### 4.3 后台网页

后台网页继续使用 `apps/admin-web/src/styles.css` 的现有绿色主题：

- 原生可用文字 `button` 的基础样式进入绿色体系。
- `.primary` 保持现有主绿色。
- `.secondary-action`、普通 `.action-button` 等可用低强调按钮改为绿色低强调样式。
- `.danger`、禁用态、纯图标/关闭按钮保留各自语义。
- 组件局部规则仅保留布局差异，减少重复声明中性色。

## 5. 审计与分类流程

审计按源代码而不是只按页面截图执行：

1. 枚举业务源文件中的 `button`、`t-button` 和按钮类名。
2. 记录每个按钮的文本、交互处理器、`disabled` 条件、主题/class 和局部样式来源。
3. 分类为可用文字操作、禁用、危险、纯图标或非按钮型控件。
4. 将可用文字操作与工作中的绿色参考实现逐项比较。
5. 修复中性默认值、局部覆盖和 TDesign 变量缺失。
6. 对无法由静态文本确定语义的动态按钮进行人工核对。

静态审计只检查业务源文件，排除构建产物、第三方组件、设计稿、证据截图和生成目录。

## 6. 交互与状态要求

本次不改变按钮的业务处理函数、导航目标、权限判断或请求载荷。

颜色必须跟随真实状态：

- 可点击时呈绿色。
- `saving`、`loading`、`busy` 或表单条件使按钮不可操作时，必须同时进入真实禁用状态并呈灰色。
- 若现有按钮只添加灰色 class 却仍响应事件，需要补齐禁用属性或事件守卫。
- 若现有按钮因条件不足不可执行却仍呈绿色，需要补齐禁用状态。
- 提交完成或条件恢复后，按钮重新变为绿色。

相册隐私页“保存设置”在 `saving === false` 时必须呈现深绿可用态，在 `saving === true` 时呈现灰色禁用态。

## 7. 自动化回归约束

新增一个聚焦按钮颜色语义的项目检查脚本及对应 Node 测试，覆盖：

- 小程序全局可用、低强调、禁用、危险四种样式契约。
- TDesign 业务按钮具有显式绿色主题路径，不依赖默认灰色。
- 已知可用文字按钮类不得声明中性灰/白背景作为最终可用态。
- 后台网页的基础、主要和低强调可用按钮都属于绿色体系。
- 禁用按钮仍为中性灰，危险按钮仍为红色。
- 截图复现点“保存设置”具备绿色可用态和真实禁用绑定。
- 共享聊天组件的应用源与包源保持一致。

检查脚本使用明确的业务目录和允许列表。例外必须按具体选择器或具体文件登记，并写明属于危险、纯图标、系统控件或非按钮型控件；不允许使用大范围目录豁免。

静态检查用于阻止明确的回归，不能替代构建和页面运行验证。

## 8. 验证与验收

### 8.1 自动验证

- 先新增回归测试并确认它会因当前灰色可用按钮而失败。
- 修复后运行新测试和按钮静态检查。
- 运行小程序现有相关检查及完整构建。
- 运行后台网页现有测试及完整构建。
- 运行共享聊天组件的一致性/相关测试。
- 对改动文件执行语法检查，并复查最终 diff 不包含无关文件。

### 8.2 页面验收

至少检查以下代表性场景：

- 相册隐私页：可用“保存设置”为现有深绿；保存中为灰色禁用；“停止分享”等危险操作为红色。
- 车局创建/设置流程：下一步、保存、搜索等可用文字按钮为绿色；缺少必要输入时为灰色禁用。
- 车局详情和管理页：普通操作为绿色，删除/解散等危险操作为红色。
- 相册、游后感和分享流程：分享、发布、下一步等可用按钮为绿色。
- 聊天扩展：发送、保存等可用操作为绿色；不可发送时为灰色。
- 我的页面和管理员目录：普通可用操作为绿色，危险操作为红色。
- 后台网页：主要与低强调文字按钮均属于绿色体系；禁用和危险状态可清楚区分。

验收重点是按钮状态语义一致和整体美术协调，不要求所有绿色按钮使用完全相同的亮度、尺寸或阴影。

## 9. 风险与控制

- **误把非按钮控件改绿**：先按语义分类，使用具体选择器允许列表，不做全局 `button` 无差别强制覆盖。
- **TDesign 内部样式覆盖宿主样式**：通过现有 CSS 变量或 `custom-style` 显式设置，并用构建产物/运行页面验证。
- **主次层级变弱**：通过深绿与浅绿、尺寸、位置和阴影维持层级，不退回灰色。
- **禁用态只改颜色未禁用交互**：测试同时检查 `disabled`/守卫和灰色样式。
- **共享组件双份源漂移**：同步修改并运行一致性检查。
- **修改范围过大**：只处理按钮颜色和与颜色直接相关的状态绑定，不进行页面布局或组件体系重构。

## 10. 非目标

- 不重做页面布局、字体、卡片、导航或图标。
- 不引入新的 UI 框架。
- 不把所有绿色值强制合并成唯一色号。
- 不修改第三方 TDesign 或 uv-ui 源码。
- 不改变按钮背后的业务权限、接口和数据模型，除非发现“视觉禁用但仍可交互”的直接状态缺陷。
- 不处理仅存在于历史文档、设计导出或截图中的按钮。
